\f0\b \cf2 \cb3 \strokec2 ## Accuracy
\f1\b0 \cf4 \cb1 \strokec4 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 Accuracy for a given element and annotator is defined as:\cb1 \
\
\cb3 ```\cb1 \
\cb3 accuracy = count(source == 1 AND annotator == 1)\cb1 \
\cb3            / count(source == 1)\cb1 \
\cb3 ```\cb1 \
\
\cb3 This is a proportion in [0, 1]. It measures the fraction of source-confirmed findings that\cb1 \
\cb3 the annotator correctly captured. Findings absent from the source document are excluded\cb1 \
\cb3 from both the numerator and denominator.\cb1 \
\
\pard\pardeftab720\partightenfactor0

\f0\b \cf2 \cb3 \strokec2 ## Confidence intervals - Agresti-Coull (adjusted Wald)
\f1\b0 \cf4 \cb1 \strokec4 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 Every accuracy proportion is reported with a 
\f0\b \cf5 \strokec5 **95% confidence interval**
\f1\b0 \cf4 \strokec4  computed using\cb1 \
\cb3 the Agresti-Coull (adjusted Wald) method via\cb1 \
\pard\pardeftab720\partightenfactor0
\cf2 \cb3 \strokec2 `statsmodels.stats.proportion.proportion_confint(method='agresti_coull')`\cf4 \strokec4 .\cb1 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 Agresti-Coull is preferred over the standard Wald interval because it maintains\cb1 \
\cb3 near-nominal coverage even for small n and proportions near 0 or 1 - which occurs\cb1 \
\cb3 frequently in per-element analyses where some elements have modest source-present counts.\cb1 \
\
\cb3 The interval is well-defined only when the number of successes does not exceed n\cb1 \
\cb3 (i.e., accuracy <= 1.0). See [\cf6 \cb3 \strokec6 Analysis Corrections\cf4 \cb3 \strokec4 ](\cf4 \cb3 \ul \ulc4 \strokec4 Analysis-Corrections\cf4 \cb3 \ulnone \strokec4 ) for the fix\cb1 \
\cb3 that ensured this invariant.\cb1 \
\
\pard\pardeftab720\partightenfactor0

\f0\b \cf2 \cb3 \strokec2 ## Paired comparison - McNemar's test
\f1\b0 \cf4 \cb1 \strokec4 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 Human and AI annotations are 
\f0\b \cf5 \strokec5 **paired**
\f1\b0 \cf4 \strokec4 : both annotators evaluated the same cases. The\cb1 \
\cb3 correct test for paired binary outcomes is 
\f0\b \cf5 \strokec5 **McNemar's test**
\f1\b0 \cf4 \strokec4 , not a two-proportion z-test.\cb1 \
\
\cb3 The test 2x2 table is built per element from source-present cases where both annotations\cb1 \
\cb3 are observed:\cb1 \
\
\cb3 |  | AI accurate | AI inaccurate |\cb1 \
\cb3 |---|---|---|\cb1 \
\cb3 | 
\f0\b \cf5 \strokec5 **Human accurate**
\f1\b0 \cf4 \strokec4  | n11 | n10 |\cb1 \
\cb3 | 
\f0\b \cf5 \strokec5 **Human inaccurate**
\f1\b0 \cf4 \strokec4  | n01 | n00 |\cb1 \
\
\cb3 The test statistic uses only the discordant cells (n10 and n01). For **small discordant\cb1 \
\cb3 counts** (n10 + n01 < 25) the 
\f0\b \cf5 \strokec5 **exact (binomial) variant**
\f1\b0 \cf4 \strokec4  is used via\cb1 \
\pard\pardeftab720\partightenfactor0
\cf2 \cb3 \strokec2 `statsmodels.stats.contingency_tables.mcnemar(exact=True)`\cf4 \strokec4 . For larger counts the\cb1 \
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 standard chi-squared approximation is used (\cf2 \strokec2 `exact=False`\cf4 \strokec4 ).\cb1 \
\
\pard\pardeftab720\partightenfactor0

\f0\b \cf5 \cb3 \strokec5 **Interpretation**
\f1\b0 \cf4 \strokec4 : a significant p-value (conventionally p < 0.05) indicates that human\cb1 \
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 and AI accuracy differ on that element more than would be expected by chance.\cb1 \
\
\pard\pardeftab720\partightenfactor0

\f0\b \cf2 \cb3 \strokec2 ## Column mapping for McNemar
\f1\b0 \cf4 \cb1 \strokec4 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 A key correctness requirement is that the McNemar table is built from the actual column\cb1 \
\cb3 names in the workbook, not from display labels. The notebook uses an explicit\cb1 \
\pard\pardeftab720\partightenfactor0
\cf2 \cb3 \strokec2 `element -> (human_col, ai_col, source_col)`\cf4 \strokec4  map. See [\cf6 \cb3 \strokec6 Analysis Corrections\cf4 \cb3 \strokec4 ](\cf4 \cb3 \ul \ulc4 \strokec4 Analysis-Corrections\cf4 \cb3 \ulnone \strokec4 )\cb1 \
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 for the history of the bug where column names were reconstructed from display labels and\cb1 \
\cb3 mismatched the schema.\cb1 \
\
\pard\pardeftab720\partightenfactor0

\f0\b \cf2 \cb3 \strokec2 ## Summary of statistical choices
\f1\b0 \cf4 \cb1 \strokec4 \
\
\pard\pardeftab720\partightenfactor0
\cf4 \cb3 | Aspect | Method | Library |\cb1 \
\cb3 |---|---|---|\cb1 \
\cb3 | Accuracy | proportion = accurate / source-present | pandas |\cb1 \
