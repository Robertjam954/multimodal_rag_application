# Code-review notes

- src/data collection and processing/pull_tcga_brca_cbioportal.py is a local cBioPortal snapshot utility, not the target benchmark. It normalizes clinical long records before checking duplicate entity-attribute keys and pivoting, then records request retries in manifest.json.
- src/extraction/stage_missingness.py is the Stage 0 JSON normalizer. It atomically publishes a report validated against schemas/missingness_stage.schema.json; its input parser rejects duplicate object keys and rejects nonstandard constants except intentional NaN to null normalization.
- src/analysis/evaluate_extraction_model_accuracy.py is explicitly a local pre-benchmark reporter, not run-store integrated. It binds three prediction payloads to a raw-byte golden SHA-256, scores only source_present: true, and limits inference to three overall case-level BH-adjusted McNemar tests.
- Extraction schemas now define strict nested summary records in schemas/extraction_model_comparison.schema.json; validate generated summaries before publication.
- tests/unit/test_json_staging_and_evaluation.py covers mocked cBioPortal retry and clinical-pivot rejection plus Stage 0 strict JSON and three-comparison evaluation. It does not assert the intended acceptance of empty Aim 1 arrays.
- pull_tcga_brca_cbioportal.py now records a canonical pre-normalization source checksum in missingness_report.json, while manifest.json stores each emitted file checksum. Clinical long records retain GET and clinicalDataType provenance in DATASET_REQUESTS.
- Aim 1 named array schemas deliberately permit empty arrays and the unit test exercises this. The stager still lacks cross-field count checks (mutated count less than or equal to its cohort n) and accepts impossible statistics.
- evaluate_extraction_model_accuracy.py heatmap bin luminance is monotone, but its white 8-point labels on #009E73 (0.4 to less than 0.6 bin) have 3.42:1 contrast; choose label color by mapped-bin luminance.
- stage_missingness.py now emits source_representation and computes source_checksum over decoded canonical pre-normalization records. Its current source_filename appends .pre_normalization_records to the actual input basename, producing a nonexistent filename; preserve the real basename and use source_representation for this distinction.
- 2026-09-09: Aim 1 stager semantic validation uses logical table names, constrains mutated counts to positive denominators, recomputes both prevalences and finite PR at 1e-12 tolerance, rejects zero reference prevalence, and checks positive ordered OR intervals plus nonnegative ordered PR intervals. The source-name check permits UUID prefixes by matching the logical table-name suffix.
